## Qlib Web Console 前端功能设计

本文档定义了 Qlib Web Console 的核心前端功能模块、用户交互及技术实现要点。

---

### 1. 仪表盘 (Dashboard)

* **功能**:
    * 作为应用首页，提供系统概览。
    * 展示关键信息卡片：例如“进行中的任务数”、“已完成的实验总数”。
    * 提供“新建实验”的快捷入口。
    * 显示最近5条实验记录列表，并可点击直接跳转至详情页。

* **实现方式**:
    * **组件**: 使用 Element Plus 的 `el-card` 构建信息卡片，`el-table` 展示最近记录。
    * **API**: 页面加载时，调用 `GET /api/dashboard/summary` 获取统计数据和最近实验列表。

---

### 2. 新建实验 (Create Experiment)

* **功能**:
    * 通过向导式表单，引导用户完成回测配置。
    * **数据配置**: 提供下拉框选择预设的股票池（如沪深300），并使用日期选择器设定回测的起止时间。
    * **模型与策略配置**: 提供下拉框选择 qlib 中已支持的模型和策略。根据所选策略，动态生成对应的参数输入项（如 `topk`, `n_drop_days`）。
    * **提交任务**: 用户点击“启动回测”按钮，表单数据被提交到后端，创建异步计算任务。

* **实现方式**:
    * **组件**: 使用 `el-form` 配合 `v-if` 或动态组件 `<component :is="...">` 来实现动态参数表单。使用 `el-select`, `el-date-picker`, `el-input-number` 等表单组件。
    * **API**:
        * 页面加载时，调用 `GET /api/config/options` 获取可选的股票池、模型、策略列表。
        * 点击提交按钮时，对表单进行校验，然后调用 `POST /api/experiments`，将配置作为 JSON 发送。成功后提示用户并跳转至历史记录页。

---

### 3. 历史记录 (Experiment History)

* **功能**:
    * 以表格形式集中展示所有已创建的实验任务。
    * **核心字段**: 实验名称、创建时间、完成时间、任务状态（排队中、运行中、已成功、已失败）。
    * **实时状态更新**: 表格能自动刷新运行中任务的状态，无需用户手动刷新页面。
    * 提供搜索和筛选功能，方便用户快速定位特定实验。
    * 每条记录提供“查看详情”和“删除”操作。

* **实现方式**:
    * **组件**: 使用 `el-table` 展示数据，并集成 `el-pagination` 进行分页。
    * **API**:
        * 调用 `GET /api/experiments` 获取实验列表。
        * 使用 `setInterval` 定时器，每隔5-10秒轮询 `GET /api/experiments?status=running` 接口，更新表格中运行中任务的状态。
        * 点击“查看详情”按钮，通过 `Vue Router` 导航到 `'/experiment/:id'` 路径。

---

### 4. 实验详情 (Experiment Details)

* **功能**:
    * 全方位、可视化地展示单次回测的详细结果。
    * 使用标签页 (Tabs) 对内容进行分类，保持页面清晰。
    * **概览 (Overview)**: 展示本次回测的核心绩效指标(KPI)，如年化收益、夏普比率、最大回撤等，并列出本次运行的完整参数配置。
    * **性能图表 (Performance)**: 绘制账户累计收益率与基准收益率的对比曲线图。
    * **持仓分析 (Positions)**: 以表格形式展示详细的每日持仓记录或换仓记录。
    * **日志 (Logs)**: 显示 qlib 在后台执行时的原始输出日志，用于调试和问题追溯。

* **实现方式**:
    * **组件**: 使用 `el-tabs` 进行内容分区。使用 `el-descriptions` 展示KPI和参数。
    * **图表**: 引入 **Apache ECharts** 库，专门用于绘制性能曲线图。
    * **API**:
        * 进入页面时，首先调用 `GET /api/experiments/:id` 获取实验的总体信息和KPI。
        * 当用户切换到不同标签页时，再按需加载对应的数据。例如，切换到“性能图表”页时，才调用 `GET /api/experiments/:id/artifacts/performance` 获取图表所需的序列数据，避免一次性加载过多数据。
